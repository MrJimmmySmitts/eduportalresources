Case study — Northbridge Rail Systems

Northbridge Rail Systems has 60 staff and builds scheduling software used by three regional rail operators. Its current practices are as follows.

Developers work directly on a single shared server, which also runs the live scheduling system the three operators depend on. That server holds real passenger contact details, and developers use those records as test data because, as one put it, "it's more realistic than making stuff up". Source files are shared through a network drive using dated folder names such as scheduler_v4_final_fixed; any developer can copy files from that drive onto the live server. Two senior developers hold the administrator password for the live server, and it is written on a whiteboard in the development room so nobody gets locked out. The server's operating system was last updated in 2021, because a restart would interrupt scheduling for the operators. Changes are checked over by whoever happens to be free before a release; last month a release went out with no check at all, because the deadline had moved forward. Passenger contact details are stored in the database as plain text. All staff sign in with a username and password only.
